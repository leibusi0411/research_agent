# Define node prompts as code prompt builders

> 演进注记（2026-09-09，R-233）：迁移到原生 function calling 后，两处表述失效，正文已就地改为现状。(1) "schema repair remains a one-time fallback LLM call" 不成立——schema repair 机制已整体删除：LLM 调用/解析失败时原 prompt 盲重试一次（共 2 次），耗尽报 `llm_call_failed`；validator 失败立即抛 `schema_validation_failed`（src/research_agent/web/role_invocation.py:30-56）。(2) "prompts instruct the model to return JSON matching the schema without Markdown" 不再准确——prompt 现为自然语言指令，schema 约束由 `complete_tool` 的 tools 参数承载（src/research_agent/core/providers.py:152-164），输出校验在 validator。prompts 仍为代码常量（prompt builder 函数、非外部可编辑文件）这一核心决策不变。

V1 Web Research prompts for Planner, ResearchExecutor, Supervisor, and Curator will be defined as code-level prompt builder functions in a prompts module rather than external user-editable prompt files. Builders such as `build_planner_prompt(...)`, `build_executor_prompt(...)`, `build_supervisor_prompt(...)`, and `build_curator_prompt(...)` generate natural-language prompts; the output schema constraint is carried by the native function-calling `tools` parameter of `complete_tool`, and output validation happens in the validator. There is no schema repair call: on LLM call or parse failure the same prompt is retried once blindly (two attempts total), and exhaustion raises `llm_call_failed`; schema validation failure raises `schema_validation_failed` immediately.

Planner prompts ask for `research_title` and subtask question drafts only. They must not ask the model to produce `subtask_id`, `status`, or `goal`; runtime normalization assigns stable subtask IDs and initial `pending` status.

Initial Planner prompts ask for 3-5 subtask drafts. Plan Revision prompts ask for 1-3 new subtask drafts to append to the existing plan. These counts guide model output but are not separate runtime hard limits.
