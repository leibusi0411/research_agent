# Let CLI stream research progress without requiring a daemon

The v1 CLI does not require a permanently running local service, but `research-agent local`, `research-agent web`, and `research-agent both` should keep running and display Research Progress Stream updates until completion. They should reuse the same Core Service application layer and phase progress semantics as the Web UI SSE endpoint, even if the first implementation streams progress records in-process rather than through a daemon. Local RAG and Web Research are separate task families, so a Local RAG task and a Web Research task may run concurrently. `research-agent both "question"` starts both families for the same question as independent tasks and displays separate progress sections. The CLI returns a busy error only when starting a second task in the same family, or when Local RAG conflicts with an active `kb rebuild`.

`research-agent both` prints separate final statuses for the Local RAG task and Web Research task. The command exits `0` only when both tasks complete successfully. If either task fails, including Web Research failing with `file_write_error` because its Web Report File could not be written, `both` exits non-zero while still showing any successful task's result.
